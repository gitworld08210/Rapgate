## High-level view

The reminder toggle handlers (`_togglePushup`, `_toggleFoodLog`, `_toggleWater`) call `setState` before awaiting the notification service. If `flutter_local_notifications` throws (permission denied on Android 13+, platform channel failure), the toggle shows "enabled" while the notification was never scheduled. Low severity — `zonedSchedule` typically no-ops silently rather than throwing — but on edge cases (permission revoked mid-session, device policy restrictions), the user sees a mismatched toggle.

No explicit `POST_NOTIFICATIONS` permission request exists for Android 13+. The iOS side is covered by `DarwinInitializationSettings`, but Android fresh installs targeting SDK 33+ will silently suppress all scheduled notifications until the user manually grants permission in system settings.

## Reminder toggle error path

The three toggle methods in `reminder_settings_screen.dart` follow this pattern:

```dart
Future<void> _togglePushup(bool value) async {
  setState(() => _pushupEnabled = value);
  if (value) {
    await _notificationService.scheduleDailyPushupReminder(_pushupTime);
  } else {
    await _notificationService.cancelPushupReminder();
  }
}
```

`setState` commits the UI change synchronously, then the `await` can fail. On failure, the widget displays an enabled toggle with no backing notification. A minimal fix:

```dart
Future<void> _togglePushup(bool value) async {
  setState(() => _pushupEnabled = value);
  try {
    if (value) {
      await _notificationService.scheduleDailyPushupReminder(_pushupTime);
    } else {
      await _notificationService.cancelPushupReminder();
    }
  } catch (e) {
    setState(() => _pushupEnabled = !value);
  }
}
```

## Android 13 notification permission

`flutter_local_notifications` version 17.x provides `requestNotificationsPermission()` on the Android plugin implementation, but it must be called explicitly. The current `initialize()` does not call it. On Android 13+ (API 33), notifications scheduled via `zonedSchedule` are silently suppressed until the user grants `POST_NOTIFICATIONS`. The reminder settings screen would be the natural place to request this permission before scheduling the first notification.
